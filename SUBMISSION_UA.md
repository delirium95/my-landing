# Sendset — тестове завдання AI-First Product Builder

## Посилання

- **Live product:** `LIVE_URL`
- **Landing page:** `LIVE_URL` (лендинг та продукт на одній сторінці)
- **Video walkthrough:** `LOOM_URL`

## Що це

**Sendset — це 60-секундна перевірка файлів перед відправленням клієнту.** Користувач додає неохайну пачку файлів, переглядає запропоновані назви та знайдені точні дублікати, а потім завантажує один client-ready ZIP із текстовим manifest-файлом. Реєстрації немає; вміст файлів обробляється локально у браузері й не завантажується на сервер.

## Проблема, для кого і як я знаю, що вона реальна

Фрилансери та невеликі client-facing команди отримують файли через Telegram, email, shared drives і кілька раундів правок. У момент передачі хороша робота часто лежить у папці з назвами на кшталт `proposal_FINAL_final_v7 (2).pdf`, маркерами `copy`, різними розділювачами та випадковими точними дублями. Через це останні 10 хвилин перед відправленням витрачаються на механічне прибирання — або клієнт отримує пакет, який виглядає недбало.

Я знаю цю проблему з власного workflow: на старті завдання у моїй папці Telegram Downloads було **499 файлів; 98 назв мали явні маркери копій**, а ще 18 були непрозорими hash/number-like назвами. Тобто це не проблема, придумана під демо — її можна буквально порахувати у робочій папці.

## Один core loop

1. Додати файли або натиснути **Load a messy demo**.
2. Переглянути readable / web-safe / minimal пропозиції, вручну поправити будь-яку назву та вирішити, що включати.
3. Завантажити один чистий ZIP; точні дублікати пропускаються, а `sendset-manifest.txt` фіксує всі зміни.

## Що свідомо не будував

Немає акаунтів, оплат, cloud-бібліотеки, admin panel, destructive-доступу до оригінальної папки та AI API. Вміст документів не читається моделлю. Я залишив один короткий, передбачуваний сценарій, який незнайома людина може завершити в першу хвилину.

## Технічна реалізація

- TypeScript у strict mode;
- Vite + JSZip;
- SHA-256 через Web Crypto API для пошуку точних копій;
- browser-only обробка файлів;
- responsive UI, перевірений на 390 px;
- 7 unit tests і 2 browser end-to-end tests, включно з реальним завантаженням та перевіркою ZIP.

## Короткий сценарій відео (до 3 хвилин)

### 0:00–0:20 — проблема

«Це Sendset — короткий pre-send check для файлів. Ідея зʼявилась не з brainstorm: у моїй Telegram Downloads папці 499 файлів, і 98 із них мають `(2)`, `copy` або інші маркери копій. Перед клієнтською передачею це або ручна рутина, або неохайне перше враження».

### 0:20–0:45 — landing page

Показати headline, обіцянку “one clean, client-ready package”, позначку **Local only** та відсутність signup wall. Коротко сказати: «Лендинг і продукт — одна сторінка, тому core loop починається одразу».

### 0:45–1:35 — core loop

Натиснути **Load a messy demo**. Показати 4 вхідні файли, 3 включені у handoff, 1 exact duplicate skipped. Перемкнути **Readable → Web-safe → Minimal fix**, повернути Readable і вручну відредагувати одну назву. Наголосити, що система пропонує, а не приховує рішення.

### 1:35–2:05 — результат

Натиснути **Download clean set**, відкрити ZIP і `sendset-manifest.txt`. Показати відповідність original → delivered та рядок про пропущений exact duplicate.

### 2:05–2:35 — рішення по scope

«Я свідомо не додавав акаунти, cloud storage чи AI-читання документів. Для цієї проблеми deterministic browser-side правила швидші, безкоштовні, пояснювані й не виносять конфіденційні файли з пристрою. Один use case, завершений до кінця».

### 2:35–2:50 — завершення

Прокрутити до трьох принципів і закінчити: «Хороша робота заслуговує на handoff, який виглядає так само добре».
